# Welt-Swing Long DEV — Instrument Resolution KRX v0.10

## Status / Zweck

v0.10 ist eine **enge deterministische Remediation- und Klassifikationsstufe für die 92 verbleibenden KOSPI-200-Zeilen** aus der eingefrorenen v0.9-Restqueue.

Sie ändert weder die fachliche Master-Spezifikation `WELT-SWING LONG DEV v0.1` noch Welt-Swing v7.2.

## Frozen Input

Aus v0.9:

- Manual Review: **667**
- Strict candidates: **2.020**
- KR_KOSPI200: **92**
- Strict freeze: **false**
- P0: **false**

Die vollständige Eligibility-Basis bleibt die eingefrorene v0.8-Datei. v0.9 war Evidence-Probe und hat keine Entscheidungen verändert.

## Warum v0.10 zuerst Korea bearbeitet

v0.9 hat für KRX HTTP 400 geliefert. Die in der KRX-All-Stock-Basic-Information-Datenstruktur benötigten Felder sind jedoch klar definiert:

- `ISU_SRT_CD` — Short Code
- `SECUGRP_NM` — Security Group
- `KIND_STKCERT_TP_NM` — Stock-Certificate Kind

Die Remediation reduziert den Request auf die minimale öffentliche Bulk-Form:

- `bld=dbms/MDC/STAT/standard/MDCSTAT01901`
- `mktId=STK`

Keine per-Security-Abfragen.

## Deterministische v0.10-Regeln

Nur exakte sechsstellige Code-Matches werden verwendet.

### PASS

`SECUGRP_NM = 주권` **und** `KIND_STKCERT_TP_NM = 보통주`

→ `COMMON_STOCK_BY_KRX_STOCK_KIND`

### FAIL

`SECUGRP_NM = 주권` **und** `KIND_STKCERT_TP_NM` enthält `우선주`

→ `PREFERRED_STOCK_BY_KRX_STOCK_KIND`

### NOT_VERIFIED

- kein exakter KRX-Code-Match,
- anderes `SECUGRP_NM`,
- anderes/fehlendes `KIND_STKCERT_TP_NM`,
- KRX-Quelle nicht materialisiert.

Keine Namensheuristik. Keine Indexmitgliedschaft als Ersatz. Keine implizite PASS-Annahme.

## Source-Block-Verhalten

Schlägt der offizielle KRX-Bulk-Request fehl, gilt:

- zero new decisions,
- KR 92 bleiben in der Review Queue,
- Strict candidates bleiben 2.020,
- Run endet kontrolliert als `...COMPLETE_WITH_SOURCE_BLOCK`,
- P0 bleibt aus.

Damit ist die Stufe fail-closed und auditierbar.
